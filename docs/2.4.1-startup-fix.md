# LocalLink 2.4.1–2.4.2 启动与界面资源修复

## Windows 根因

2.4.0 workspace EXE 中包含来自构建环境 Poppler 的 `icuuc.dll` / `icudt78.dll`。
Qt6Core 导入不带版本后缀的 Windows ICU 函数，该外部 DLL 缺少这些导出，触发 QtCore 导入失败。
修复打包规则：不收集同名外部 ICU，使用 Windows 系统 ICU；统一使用 Qt 随附的 VC 运行库，避免 Python 目录中的旧版本覆盖。
没有修改系统 DLL、PATH、防火墙或信任数据。

新增 EXE 自检入口 `--self-test <报告绝对路径>`，在临时本地数据目录、随机回环端口加载 Qt、WebEngine 与内置网页，不启动局域网发现或修改防火墙。

## Android 入口

原启动入口仍是原生设备列表，新记录界面需要进入本机收件箱或连接新主机后才显示。
现在普通启动先等待本机服务就绪，直接进入新版工作台；设备列表保留在顶栏，系统分享进入时仍优先选择接收设备。
服务启动超时返回设备列表，保留重试路径。WebView 禁用 HTTP 缓存，不清除用户数据。

版本名 2.4.1、版本号 10。请覆盖安装新 APK，不要先卸载。连接旧电脑服务时仍会显示该旧服务提供的页面，因此建议两端一起升级。

## 2.4.2 双端界面资源修复

Android 本机 HTTP 服务的静态资源白名单遗漏 `workspace.css`，但 `index.html` 已经改为引用该文件。结果是样式请求返回 404：隐藏状态、手机分页、灰白主题和响应式布局全部失效，旧装饰元素还会以无样式 SVG 显示成黑色三角。修复后，服务器允许安全文件名的 HTML/CSS/JS 与图像资源，防止后续新增主题文件再次漏配；路径穿越与 JSON 等数据文件仍被拒绝。

Windows 截图来自 `dist` 根目录保留的旧通用 EXE。2.4.2 除版本化目录外，同步更新根目录的 `LocalLink-Portable.exe` 通用入口；窗口标题包含 2.4.2，用于肉眼确认没有误开历史包。

Android 版本名 2.4.2、版本号 11；APK 内已检查包含 `index.html`、`workspace.css` 和 `app.js`。
