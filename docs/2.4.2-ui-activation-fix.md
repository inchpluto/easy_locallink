# LocalLink 2.4.2 双端界面生效修复

## 原因

- Android 的 `index.html` 已引用 `workspace.css`，但手机本机 HTTP 服务的静态资源白名单没有该文件。CSS 请求返回 404 后，隐藏、分页、响应式与主题样式全部失效，因此连接页和主页同时出现，未受样式控制的图形显示为黑色三角。
- Windows 的 `dist` 中同时保留多个历史 EXE；截图中的深色控制台来自旧的通用文件，并非 2.4.1 版本目录中的新构建。

## 修复

- Android 静态资源服务允许安全文件名的 HTML、CSS、JavaScript 和界面图像，同时继续拒绝目录穿越与数据文件。
- Android WebView 使用无缓存加载，普通启动进入本机工作台；顶栏仍可返回设备列表。
- 版本更新为 2.4.2（versionCode 11），标题显示版本用于核对。
- Windows 窗口标题更新为 `LocalLink 2.4.2`。
- `dist/LocalLink-Portable.exe` 与 `dist/LocalLink-Android-debug.apk` 已同步为 2.4.2，不再指向旧构建；历史版本化文件未删除。

## 验证

- Android 资源白名单单元测试通过，APK 中实际包含 `assets/index.html`、`assets/workspace.css` 和 `assets/app.js`。
- Android Debug APK 构建成功，v2 签名有效，版本信息为 2.4.2 / 11。
- Windows 打包后的 EXE 自检成功加载 Qt 6.11.1、WebEngine、新版 `workspace.css` 与记录搜索组件。
- JavaScript 两套测试、Python 21 项测试通过。

当前未连接 Android 真机，因此真机覆盖安装与局域网端到端传输仍需用户实测。安装时请覆盖旧包，不要先卸载，以保留应用数据。
